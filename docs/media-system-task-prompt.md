# ASTREVA 官网媒体系统改造任务提示词

你在 `<repo>` 中工作。先盘点现有媒体位、后台编辑字段、公开内容 API、上传服务、静态构建和多语言流程；保留工作区已有修改，不覆盖用户数据。按下面要求直接实现、验证并报告实际完成范围。

## 目标

官网中承载照片或视频的视觉区域，都由后台统一管理。编辑者能在同一媒体位添加、上传、输入外部链接、替换、排序、删除多项媒体，并为每项选择图片或视频。配置为空时使用项目内的默认素材；配置后只显示后台选择的素材，不再混入默认图。一个媒体位有多张图片时自动轮播，支持手动切换、暂停与无障碍操作。每个视频可选“点击播放”或“静音自动播放”，YouTube watch、shorts、youtu.be 链接能在站内播放，且始终提供“在 YouTube 打开”入口。浏览器禁止自动播放时保留可点击播放入口。

## 现状与缺口

- 现有内容模型分散使用 `backgroundImage`、`backgroundVideo`、`coverImage`、`galleryImages`、`galleryVideos`、`videoUrl`、`videoImage`，多数区域只有单 URL 输入；`SchemaForm` 没有统一的多媒体列表控件。
- 首页、内部页首屏、产品中心、品类、产品卡片与详情、解决方案、关于我们子页入口、行动区、视频弹窗都有视觉媒体位；Logo 与 SEO 分享图保留图片专用语义，但必须继续能在后台上传、替换与清空。
- `ProductCenterView` 当前只显示 `hero.backgroundImage`，忽略已经存在的 `hero.backgroundVideo`。
- `SolutionsView` 在没有视频 URL 时显示不可点击的播放图标，容易误导访客。
- 产品图库在后台以多行 URL 保存，前台平铺展示；缺少排序 UI、单项播放模式和统一轮播。
- 现有默认图是单张映射；各媒体位需要多张符合排水系统、产品形态和 ASTREVA 深蓝工业风格的本地默认/备选图。

## 数据与兼容性

定义统一 `MediaItem`：`type: image|video`、`url`、`poster?`、`alt?`、`playback: click|muted-autoplay`。各媒体位存 `mediaItems?: MediaItem[]`，数组顺序即播放顺序。保留旧字段读取兼容：新列表缺失时读旧图/视频；新列表显式配置后优先使用新列表；新旧数据均为空时使用本地默认素材。保存产品和品类时不得丢弃新媒体字段。编辑器允许一键从旧字段导入当前内容，随后独立编辑新列表。SEO/翻译不能把 URL、播放方式和排序当作待翻译文案；`alt` 可以随正文翻译。媒体删除引用检查必须识别列表中的 URL 与 poster。

## 后台交互

为每个实际视觉媒体位增加同一个“媒体列表”编辑器：新增图片/视频；从现有素材库选取；本地上传；粘贴 URL；编辑 alt、封面、播放方式；上移/下移；删除单项；清空列表；预览结果。图片选择器只接受图片，视频选择器接受视频文件或规范化的 YouTube URL。上传失败时保留编辑内容并显示错误。区分“移出此位置”和“从素材库删除文件”，避免误删被其他区域使用的资产。页面原有文案、详情和所有语言的结构继续可编辑。

## 前台行为

建立复用媒体组件，应用到所有实际视觉位置，保持目前页面布局和响应式风格。图片多于一张时定时轮播，手动前后切换与圆点跳转，用户操作时重置计时；`prefers-reduced-motion` 下不自动切换。视频按项设置播放：点击模式显示封面/播放按钮，点击后加载播放器；自动模式始终静音、内联播放、循环，失效时显示封面与播放按钮。YouTube 使用受限的 `youtube-nocookie.com` 嵌入地址、`mute=1` 自动播放参数，并给出原始 YouTube 链接；仅允许可信 YouTube 域名。离屏视频不继续播放；切换幻灯片时停止前一个视频。所有图片提供合适 alt、尺寸策略与懒加载，首屏优先加载。不要让轮播控件嵌入链接造成无效 HTML 或误导航。

## 默认与生成素材

为首页首屏、产品介绍、产品中心、解决方案各场景、关于我们、制造/品质、安装/质保/支持、每个产品品类和产品创建至少两张相符的备选照片。生成图作为项目本地默认素材进入 `frontend/public/assets/`，文件名明确、不要覆盖已有素材；不伪造真实认证、尺寸、项目现场或品牌 Logo。建立按媒体位和产品 slug 查找默认素材的映射，使空配置自动轮播。默认素材也应在后台可见或能一键加入媒体位以便替换和排序。

## 验收

1. 后台选取、上传、粘贴、改类型、改播放方式、排序、删除、保存后刷新，所有媒体位状态保持一致；删除正在引用的库文件被拦截。
2. 图片一张静态显示，多张自动轮播；显式配置覆盖默认；未配置显示多张本地默认图。
3. MP4/WebM 和 YouTube 的点击播放、静音自动播放在首页、首屏、解决方案和产品页均能工作；YouTube 按钮跳转原始链接。
4. 中文、英文、阿拉伯语静态构建成功，媒体 URL 不被翻译；所有页面无空图、破图、不可点击的假播放按钮。
5. 后台测试、前台 typecheck/build 与关键真实浏览器流程通过；报告生成素材数量、覆盖范围、已知限制。

## 实施顺序与检查细则

1. 先列出页面及媒体位矩阵：首页首屏、弹窗画面与背景、首页产品卡、产品介绍、行动区；产品中心首屏与产品卡；品类首屏与产品卡；产品详情首屏、主视觉、图库与视频；解决方案首屏、视频区和场景插图；关于我们及子页；支持、安装、FAQ、质保、协议和隐私页。记录每一位的旧字段、默认图、对应后台模块。品牌标志、语言旗帜、合作伙伴 Logo、SEO 分享图仍使用图片专用控件。
2. 确立单一优先级：新媒体列表非空时只显示列表；新列表明确为空时显示本地默认图；新列表未创建时沿用旧图或视频字段；旧字段也为空时显示本地默认图。保存时保留旧字段以支持回滚，不让旧字段覆盖明确配置的新列表。
3. 后台编辑器展示顺序、预览、类型、URL、素材库、本地上传、alt、视频封面及播放模式。每次新增、替换、删除、排序都更新同一个数组；必须保存并发布才能改变官网。导入旧媒体时包括产品的多图和多个视频，移除位置引用不得删除素材库原文件。
4. 服务端在分模块及全量保存时校验列表最多 30 项、图片/视频类型、HTTP(S) 或站内路径、可信 YouTube 视频 ID、播放模式及封面 URL；拒绝空地址和危险协议。产品与品类的显式字段映射必须持久化新列表。素材库删除前遍历列表和封面引用。
5. 前台同一轮播组件处理图片、MP4/WebM 和 YouTube。轮播定时器只在可见区域运行；离屏、后台标签、切换项目时卸载或暂停视频；减弱动态效果设置下不自动切换。按钮不能嵌套在产品卡链接内。图片加载失败时回退到本地素材，自动播放失败时提供播放按钮。
6. 视频点击模式需先显示封面，用户点击才创建播放器。YouTube 只生成 `youtube-nocookie.com` 嵌入源，保留跳转原始 YouTube 链接；静音自动播放加内联、循环和静音参数。外部链接的域名必须严格匹配，不能靠字符串包含判断。
7. 本地素材按内容语义命名并压缩为 WebP；每个场景与产品至少两张视觉上不同的图。不得把生成的场景照片描述成真实施工案例、认证照片或精确产品规格图。默认素材可通过后台一键加入列表再调整顺序或替换。
8. 验证中文、英文、阿拉伯语构建和页面；检查失效图片、无效嵌套交互、轮播切换、YouTube 跳转、文件视频播放、后台保存后重新打开。后台受到 2FA 保护时只在已授权会话中验证，不绕过身份认证；未验证的操作需在交付报告中明确列出。
