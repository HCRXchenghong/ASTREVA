# 客服系统边界

## 产品边界

ServiceBridge 服务网站访客在线咨询。访客使用官网右下角入口或访客独立页；人工客服使用 Flutter “在线客服”App；管理员使用 `1337` 统一后台。官网内容管理负责客服入口文案和地址，客服管理、会话工作台与系统设置同属统一后台的独立栏目。

## 已实现

- 访客会话、消息、上传、历史、评价和 WebSocket 实时通信。
- AI 自动回复、关键词快捷回复、转人工状态和无回复回退。
- 客服 App 登录、状态、会话队列、未读、历史、文字/图片、关闭、改密与重连。
- 统一后台客服账号、数据概览、会话查看/转接/关闭/导出及基础系统设置。
- PostgreSQL 持久化、Redis 跨节点事件、对象存储、限流和运行指标。

## 尚未实现

- App 退到后台或进程被系统回收后的 APNs/FCM 推送、声音和通知跳转。
- App 中的语音发送、会话备注、消息撤回和客服主动转接界面。
- 统一后台关键词、评价和审计的完整操作页面。
- 完整端到端自动化、商店发布、备份监控、故障演练和生产容量验收。

## 安全边界

- 访客 token 只能访问绑定会话；客服只能操作自己负责的会话；管理员可以管理全部会话。
- WebSocket 必须校验来源，生产 `CORS_ALLOWED_ORIGINS` 禁止使用 `*`。
- 只有 `TRUSTED_PROXY_CIDRS` 中的代理头可作为真实访客 IP。
- 管理和客服改密、重置、禁用后必须撤销旧 token 并断开在线连接。
- 统一后台在服务端代理客服管理员请求，不向浏览器暴露客服引擎管理员密码。
- 生产凭证只能来自环境变量或密钥系统，不能写入代码、Markdown 或 Git 数据文件。

## 验收边界

“本地核心闭环完成”表示访客发起咨询、管理员创建客服、App 在线登录和接待已经验证；“商业上线”还要求系统推送、自动化测试、可观测性、备份恢复、签名发布和容量测试通过。两者不能混为同一完成状态。
