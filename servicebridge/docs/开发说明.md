# ServiceBridge 开发说明

> 版本：v1.4.5 · 更新时间：2026-11-10

## 开发入口

```bash
cd servicebridge/backend
GOCACHE=/tmp/astreva-go-cache go test ./...
STORE_DRIVER=postgres DATABASE_URL=postgres://... go run ./cmd/server
```

用户端是无构建静态页面，位于 `apps/user-web/index.html`：

```bash
python3 -m http.server 5173 --bind 127.0.0.1 --directory servicebridge/apps/user-web
```

## 约定

- 领域模型位于 `internal/domain`，业务编排位于 `internal/app`，HTTP 边界位于 `internal/httpx`。
- `store.Store` 的内存和 PostgreSQL 实现必须保持行为一致；新增接口必须同时实现并测试。
- 浏览器鉴权使用 Bearer token；访客、客服、管理员权限不能在前端替代后端校验。
- WebSocket 事件先落库再广播，`client_msg_id` 用于重试幂等。
- 数据库结构先更新 `001_init.sql` 的全新安装结果，再按需要添加可重复执行的增量迁移；当前最新为 `012_security_policy.sql`。`ensureCoreTables` 只做幂等补列，不能替代正式迁移。
- 用户端通过 meta 或同源推导 API；本地端口不是生产配置，生产应同域反代。

## 提交前

```bash
gofmt -w ./backend
cd backend && go test ./... && go vet ./...
cd .. && make compose-check
```

需要监听本地端口的测试在受限沙箱中可能失败，应在允许回环监听的环境复跑；编译错误、数据竞争和断言失败不能归类为环境限制。
