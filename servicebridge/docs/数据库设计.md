# ServiceBridge 数据库设计

## PostgreSQL

- `admin_users`：管理员账号和 bcrypt 密码。
- `agents`：客服账号、分组、状态、最大会话数和禁用时间。
- `visitors`：访客来源、原始 IP 和备注。
- `conversations`：状态、负责人、最后消息、双方未读数和关闭时间。
- `messages`：服务端/客户端消息 ID、发送者、类型、内容和撤回审计。
- `service_ratings`：每个会话唯一评价、标签和意见。
- `audit_events`：管理操作的操作者、资源、IP、User-Agent 和说明。
- `keyword_rules`：关键词匹配、回复动作和快捷问题配置。
- `contact_settings`：电话、社交联系方式、二维码和欢迎语。
- `ai_settings`：AI 模式、模型、超时、提示词和加密后的 API Key。
- `business_hours`：时区、营业起止时间和启用状态。
- `auth_sessions`：管理员/客服会话 token 和有效期。

`001_init.sql` 描述全新安装的完整结构，`002_widget_settings.sql` 兼容早期数据库增加快捷问题和欢迎语字段。

## 一致性规则

- 会话只能处于 `waiting`、`assigned`、`ai_serving`、`human_requested`、`closed`。
- 同一会话只分配一个客服，删除/禁用客服前需释放或重新分配未关闭会话。
- `(conversation_id, sender_type, client_msg_id)` 唯一，保证客户端重试不重复写消息。
- 每个会话最多一条评价。
- AI Key 使用 `DATA_ENCRYPTION_KEY` 做 AES-GCM 加密，接口只返回脱敏值。
- PostgreSQL 时间统一写 UTC，展示层按业务时区转换。

## Redis

Redis Pub/Sub 只负责多实例间的实时事件广播和登录态撤销，不是消息事实来源。断线恢复必须从 PostgreSQL 拉取历史；Redis 不可用时单实例仍可工作，多实例跨节点实时投递会受影响。

## 备份

生产至少每日全量备份 PostgreSQL，并验证定期恢复；上传目录或对象存储需要独立版本/生命周期策略。数据库迁移、应用镜像和回滚版本应绑定同一发布编号。
