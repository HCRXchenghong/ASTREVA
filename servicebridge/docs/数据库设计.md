# ServiceBridge 数据库设计

> 版本：v1.4.5 · 更新时间：2026-11-10 · 适用于迁移 `001_init.sql` 至 `012_security_policy.sql`。
> 生产存储由 PostgreSQL 承担；内存仓库仅用于测试/快速开发，重启即丢，不能用于生产验收。

## 1. 迁移顺序

| 迁移 | 内容 |
| --- | --- |
| `001_init.sql` | 管理员、客服、访客、会话、消息、评价、审计、关键词、联系方式、AI 设置、营业时间、会话 token；消息/会话语种字段与客服偏好 JSONB |
| `002_widget_settings.sql` | 访客端快捷问题、欢迎语等设置 |
| `003_api_apps.sql` | 开放 API 应用与 Key |
| `004_ai_knowledge.sql` | 多知识库、条目、知识库设置、消息知识依据 |
| `005_ai_limits.sql` | 访客/会话 AI 限额 |
| `006_service_policy.sql` | 客服策略、排队、黑名单、提醒渠道、SMTP、会话首响/SLA 字段 |
| `007_service_policy_wave2.sql` | 无人值守通知时间 |
| `008_api_app_scopes.sql` | 开放 API scope |
| `009_visitor_profiles.sql` | 访客画像与画像设置 |
| `010_ai_binding_targets.sql` | 能力绑定候选链 |
| `011_conversation_profile_visitor.sql` | 会话关联画像访客 |
| `012_security_policy.sql` | 开放 API 总开关、客服只读围观范围 |

`001_init.sql` 只保证全新安装的基础结构；生产升级必须按顺序执行增量迁移。Go 服务启动时还会通过 `ensureCoreTables` 幂等补列，不能拿它替代正式迁移。

## 2. 核心表

### 账号与会话

- `admin_users`：管理员账号、bcrypt 密码。
- `agents`：客服账号、分组、在线状态、最大会话数、偏好 JSONB、禁用时间。
- `visitors`：访客来源、IP、备注。
- `auth_sessions`：管理员/客服 Bearer token 与过期时间；服务端可撤销。
- `api_apps`：开放 API 应用、Key 前缀、scope、限流、启停。

### 会话与消息

- `conversations`：状态、负责人、最后消息、未读数、关闭时间、语种、首响时间、SLA 状态、排队分组、画像关联。
- `messages`：服务端/客户端消息 ID、发送者、类型、内容、撤回、语种与知识依据。
- `service_ratings`：每会话唯一评价、标签、意见。
- `conversation_queue`：排队会话、优先级、分组、入队原因/时间。
- `service_blacklist`：IP/账号黑名单与过期时间。

### 配置与 AI

- `service_policy`：排队、SLA、无人值守、AI/关键词优先级、开放 API 开关、围观范围。
- `contact_settings`、`business_hours`、`keyword_rules`：访客端展示与关键词回复。
- `ai_settings`：旧版单上游配置（兼容保留）。
- `ai_providers`：多供应商、加密 Key、模型、出站白名单、熔断状态。
- `ai_bindings`、`ai_binding_targets`：能力绑定与候选优先级链。
- `ai_knowledge_bases`、`ai_knowledge_entries`、`ai_knowledge_settings`：知识库。
- `ai_limits`：访客/会话 AI 限额。
- `agent_alert_channels`、`alert_smtp_settings`：提醒渠道与 SMTP。
- `visitor_profiles`、`visitor_profile_settings`：访客画像与开关。
- `audit_events`：管理操作、资源、IP、UA、说明。

`app_releases`、`device_tokens` 等表由 Go 启动时的 `ensureCoreTables` 幂等创建；新环境仍应先执行迁移，再启动服务。

## 3. 一致性规则

- 会话状态：`waiting`、`assigned`、`ai_serving`、`human_requested`、`closed`。
- 同一会话只分配一个客服；删除/禁用客服前需释放或重新分配未关闭会话。
- `(conversation_id, sender_type, client_msg_id)` 唯一，客户端重试不重复写消息。
- 每个会话最多一条评价。
- 产品/品类/FAQ 的 slug 唯一；产品 `category_slug` 必须引用存在的品类。
- AI Key、推送密钥、提醒渠道密钥使用 `DATA_ENCRYPTION_KEY` 做 AES-256-GCM 加密；接口只返回掩码。
- PostgreSQL 时间统一写 UTC，展示层按业务时区转换。
- 内容保存使用 revision 乐观锁；旧 revision 返回 409。

## 4. Redis

Redis Pub/Sub 只负责多实例间实时事件广播和登录态撤销，不是消息事实来源。断线恢复必须从 PostgreSQL 拉取历史；Redis 不可用时单实例仍可工作，多实例跨节点实时投递会受影响。

## 5. 备份与恢复

- `scripts/backup-production.sh` 备份 PostgreSQL + 默认本地媒体卷（`admin-uploads`、`servicebridge-uploads`）；
- 备份文件均带 `.sha256`，恢复前先做 SHA-256 与 gzip 校验；
- `scripts/restore-production.sh` 只恢复 PostgreSQL 到隔离库；本地媒体卷按 `docs/OPERATIONS.md` 的步骤手工解包；
- 外部 R2/S3 的版本、跨区复制和生命周期由供应商侧负责；
- 迁移、镜像和数据库备份必须绑定同一发布版本（当前 `v1.4.5`）。
