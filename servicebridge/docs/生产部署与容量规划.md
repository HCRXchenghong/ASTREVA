# ServiceBridge 生产部署与容量

## 推荐拓扑

- Caddy：直接监听 80/443 并自动签发/续期证书，负责静态用户端、API/WebSocket/开放接口反代和上传入口（仓库 `deployments/ubuntu/Caddyfile` 是配置真源，域名来自环境变量）。
- 两个及以上 Go 后端实例：无状态 HTTP/WebSocket 节点。
- PostgreSQL：账号、会话、消息、配置、评价、审计与推送配置事实库。
- Redis：跨节点实时事件广播。
- S3/MinIO：生产上传文件，避免多节点共享本地磁盘。
- Prometheus + Grafana（Compose profile `monitoring`）：采集 `/metrics`、容器状态并触发告警。

同一个客服域名应同时提供用户端、`/api/*`、`/ws`、`/open/*`（第三方开放接口）、`/uploads/*`、`/healthz` 和 `/readyz`，减少跨域配置。官网域名必须出现在 `CORS_ALLOWED_ORIGINS` 和 `FRAME_ANCESTORS`。
官网域名还需要把 `/__preview/*` 透传给官网容器，用于控制台的草稿预览。

## 安全底线

- 设置强随机 `DATA_ENCRYPTION_KEY`、启动密码、指标 token 和数据库密码。
- `CORS_ALLOWED_ORIGINS`、`TRUSTED_PROXY_CIDRS` 禁止 `*`。
- 只公开 80/443；PostgreSQL、Redis、后端实例和指标端点走内网。
- 上传限制 MIME、大小和访问域名；对象存储使用最小权限凭证。
- 入口、登录、上传和 WebSocket 建连都要有限流与告警。

## 容量验证

不要把代码中存在压测工具等同于已达到 5000 并发。上线环境按 `100 -> 500 -> 1000 -> 2500 -> 5000` 阶梯测试，记录：

- 建连成功率、建连耗时和断线率。
- 消息 ACK 平均、P95、最大延迟。
- Go 内存/协程、CPU、文件句柄和 GC。
- PostgreSQL 连接、慢查询、写入延迟和磁盘。
- Redis 发布/订阅延迟与断连。
- 反代活跃连接、上游失败和超时。

任一阶梯出现连接不足、持续错误或资源失控，应先定位再升阶。负载机自身的端口、文件句柄和出口带宽也要纳入排查。

## 运维要求

- `/healthz` 只表示进程存活，`/readyz` 同时检查存储可用性。
- WebSocket 反代读写超时要大于客户端心跳周期。
- 发布前备份；迁移失败、错误率上升或消息丢失时按镜像和数据库方案回滚。
- 定期演练 PostgreSQL 恢复、Redis 故障、单节点下线和证书续期。
